# CDD Expo Phase 1 Report — Demo entry and synthetic-data clarity

## 1. Objective

Reduce local expo startup friction while clearly identifying the synthetic
demonstration workspaces. Preserve the existing frontend/API boundary and local
authentication behavior.

## 2. Work completed

- Added Vite-development-only presets for the seeded North Campus and City
  Transport workspaces in `frontend/src/App.tsx`.
- Kept manual local identity entry available. Presets only populate the form;
  connecting still performs the existing API health and workspace requests,
  and the API remains responsible for membership validation.
- Replaced the raw organization UUID in the header with the seeded
  organization name when a preset is selected, and added a visible synthetic
  data notice.
- Added focused coverage for both preset identities, successful connection,
  and synthetic-data labeling in `frontend/src/App.test.tsx`.
- Styled the preset controls and notice in `frontend/src/styles.css`.
- Documented the local-only presets in `README.md`.
- Updated `docs/progress.md` with the phase state and observed verification.

No backend source, API contract, database schema or records, scoring logic,
authentication policy, or dependency manifest was changed.

## 3. Decisions

- Presets use the deterministic synthetic IDs already generated by
  `backend/app/seed.py`; they are included only when Vite's `import.meta.env.DEV`
  is true.
- Presets require a separate user action to connect. They do not bypass the
  existing API membership check.
- AI recommendations are not part of this phase. No AI capability is claimed
  or implied.
